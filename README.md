OkayCMS (форк v4.5.2)
----------------------

OkayCMS — PHP-платформа електронної комерції. Цей репозиторій — форк; що саме в ньому змінено,
описано нижче, у розділі «Про цей форк».

 - **Документація:** [`docs/README.md`](docs/README.md) — написана під цей форк. Апстрімний
   довідник описує апстрім і цьому коду вже не відповідає.
 - **Запуск:** [`dev/README.md`](dev/README.md) — оточення Docker, для розробки й для продакшну.
   Інших способів розгортання форк не описує.

Апстрім: [сайт](https://okay-cms.com) ·
[репозиторій](https://github.com/OkayCMS/OkayCMS) ·
[його документація](https://github.com/OkayCMS/OkayCMS/tree/master/docs)

### Швидкий старт

Потрібен Docker і Docker Compose **≥ 2.24.0** — перевірити: `docker compose version`.
На старіших Compose оточення не стартує (у конфізі є директива `!reset`, додана саме
в цій версії).

**1. Скопіювати два конфіги.** Обидва в `.gitignore`, тому їх треба зробити руками:

```bash
cd dev
cp .env-example .env
cp ../config/config.local-example.php ../config/config.local.php
```

**2. Звірити ідентифікатор користувача.** У `.env` уже стоїть `APP_UID=1000` і
`APP_GID=1000` — це типовий перший користувач у Linux. Якщо `id -u` віддає щось інше,
впишіть своє значення в `dev/.env`, інакше файли, які контейнер запише в теку проєкту,
будуть недоступні для запису з-під вашого користувача:

```bash
id -u   # якщо не 1000 — виправте APP_UID і APP_GID у dev/.env
```

**3. Показати браузеру, куди йти.** Ім'я `okaycms.loc` нікуди не резолвиться саме собою:

```bash
grep -q okaycms.loc /etc/hosts || echo "127.0.0.1 okaycms.loc" | sudo tee -a /etc/hosts
```

**4. Запустити:**

```bash
docker compose up -d
./bin/smoke.sh
```

`smoke.sh` дочекається контейнерів і перевірить, що оточення справді піднялось; має
завершитись рядком `all checks passed`. Він ходить до nginx за IP із заголовком `Host`,
тож проходить і без кроку 3 — той крок потрібен саме браузеру.

**Готово:**

| Що | Де |
| -- | -- |
| Вітрина | `http://okaycms.loc` |
| Адмінка | `http://okaycms.loc/admin`, логін `admin`, пароль `1234` |
| Пошта, що йде з сайту (Mailpit) | `http://localhost:8025` |

Ім'я хоста й порти задаються в `dev/.env` (`VIRTUAL_HOST`, `HTTP_PORT`). Докладніше про
оточення, прод-оверлей і те, що робить кожен контейнер — [`dev/README.md`](dev/README.md).

Про цей форк
----------------------

П'ять речей, які форк додає до апстрімної OkayCMS v4.5.2:

 - **PHP 8.4 і 8.5.** `composer.json` вимагає `php ^8.4`; CI ганяє тести на 8.4 і 8.5, PHPStan
   рівня 5 — на 8.5, плюс `composer audit` і скан секретів. У локальному оточенні лишився один
   сервіс `php85`, старого на PHP 7.4 більше немає.
 - **`vibe_shop` — нова тема вітрини.** Повний редизайн, адаптивний на телефонах і планшетах в
   обох орієнтаціях. Вмикається в адмінці, у розділі «Дизайн»: чиста база стартує на `okay_shop`.
   Стокова тема лишилась у комплекті, але не в стоковому вигляді: 8 файлів довелось привести до
   POST-мутацій і CSRF-токена, ще 12 розійшлись через міграцію на Smarty 5, два апстрімні баги
   й обслуговування форку. Свою тему сюди —
   [`docs/theme-porting.md`](docs/theme-porting.md); тему звідси на нефоркнуту OkayCMS 4.5.2 —
   [`docs/theme-to-stock.md`](docs/theme-to-stock.md).
 - **Освіжена адмінка.** Іконки переведені з lucide на Tabler у єдиному джерелі
   `backend/design/html/svg_icon.tpl`, шрифт один і самохостом (сторонніх запитів за шрифтами
   немає), кольори зведені в шар із 60 токенів замість hex-літералів, кільце фокуса
   `:focus-visible` з'явилось там, де його не було зовсім. Розмітку майже не чіпали.
   Що чим малювати — [`docs/admin-design.md`](docs/admin-design.md).
 - **Ітерація безпеки.** CSRF-захист і мутації вітрини лише через POST, хешування паролів
   Argon2id, куки `HttpOnly`, закриті обходи шляхів у редакторах теми адмінки, у файловому
   менеджері та в ресайзі зображень, екранування формул у CSV-експортах та інше. Це змінює
   поведінку, на яку могли покладатись стороння тема чи модуль:
   [`docs/UPGRADE-security.md`](docs/UPGRADE-security.md) перелічує, що ламається і що з цим
   робити. Міграцій бази немає, але **конфіг nginx оновити треба** — два deny-правила для
   каталогів завантажень не спрацьовували ніколи.
 - **Самооновлення ядра.** Адмінка сама перевіряє релізи форку на GitHub і вміє накотити нову
   версію однією кнопкою: із резервною копією, технічними роботами на час підміни файлів,
   перевіркою, що сайт після оновлення живий, і автоматичним відкотом, якщо ні. Ставити чи
   вмикати нічого не треба — це частина ядра (`Okay/Core/Update/`, сторінка
   «Налаштування сайту → Оновлення ядра», право менеджера `core_updater`). Оновлюються код
   ядра, адмінки й штатних модулів; дані, завантажені файли, тема вітрини та сторонні модулі
   лишаються недоторканими. Як користуватись і що робити, коли щось пішло не так —
   [`docs/updates.md`](docs/updates.md).

Робота із залежностями, яка прийшла разом із підтримкою PHP 8.5, заодно закрила вразливості, що
форк успадкував: на дофорковому lock-файлі `composer audit` показував 11 у чотирьох пакетах,
сьогодні — жодного. Шість з одинадцяти були в Smarty 3.1.40, шаблонізаторі, який виконується на
кожному запиті: серед них ін'єкція PHP-коду (CVE-2024-35226, CVE-2022-29221) і вихід із пісочниці
(CVE-2021-29454). Останні дві жили в `maximebf/debugbar` і закрилися разом із переїздом на
`php-debugbar/php-debugbar`. Тепер `composer audit` ганяється в CI на кожен PR. Пакет за пакетом —
розділ [«Залежності»](docs/UPGRADE-security.md#залежності) того самого документа.
