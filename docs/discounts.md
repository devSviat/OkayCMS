# Знижки

Система знижок централізована: вона керує послідовністю й пріоритетом застосування знижок —
і до кошика загалом, і до кожної позиції окремо. Стандартні знижки (купон, група покупця) та
знижки модулів налаштовуються однаково, якщо модуль користується спільним інтерфейсом
реєстрації.

## Знижка

### Види

| Вид | Значення | Залежить від порядку |
| --- | -------- | -------------------- |
| `absolute` | сума в грошових одиницях | ні |
| `percent` | відсоток | так |

### Режими обчислення

У кожної знижки два режими — від чого рахувати відсоток:

**Від останньої знижки** (типовий) — базою є ціна після всіх попередніх знижок.

```
Ціна 1000, знижки 10%, 20%, 30% — усі «від останньої»
1000/100*10 = 100
 900/100*20 = 180
 720/100*30 = 216
Разом: 1000 − 100 − 180 − 216 = 504
```

**Від початкової ціни** — базою завжди є початкова ціна.

```
Ціна 1000, знижки 10%, 20%, 30% — усі «від початкової»
1000/100*10 = 100
1000/100*20 = 200
1000/100*30 = 300
Разом: 1000 − 100 − 200 − 300 = 400
```

Режими можна змішувати:

```
Ціна 1000; знижка 1 (10%) і 3 (30%) — «від останньої», знижка 2 (20%) — «від початкової»
1000/100*10 = 100
1000/100*20 = 200
 700/100*30 = 210
Разом: 1000 − 100 − 200 − 210 = 490
```

Для **абсолютної** знижки режим не має значення.

### Назва й опис

Обидва — мовні змінні, обидва багатомовні. Назву бачить і менеджер, і покупець (у кошику й на
сторінці замовлення); опис типово показується лише в адмінці.

## Набори знижок

Адмінка → **Замовлення → Знижки**. Тут задається, які знижки й у якому порядку можуть
застосуватись — окремо для кошика й окремо для позиції.

Угорі сторінки — усі зареєстровані **знаки** знижок, поділені на дві групи: для кошика й для
позиції. Знак унікальний і представляє конкретну знижку.

**Набір** — це рядок зі знаків у тому порядку, в якому вони мають обчислюватись:

```
$ok_disc1 $<ok_disc2 $ok_disc3
```

| Символ | Значення |
| ------ | -------- |
| `$` | початок знака |
| `<` | режим «від початкової ціни» (типово — «від останньої знижки») |
| решта до пробілу | сам знак |

Знак можна повторювати: `$ok_disc1 $ok_disc1 $ok_disc1` застосує ту саму знижку тричі
поспіль.

### Вибір набору

Кожен набір — окрема інструкція, набори між собою не комбінуються. Виконується **перший
згори набір, усі знижки якого зараз доступні**. Не підійшов — береться наступний, і так до
кінця; якщо не підійшов жоден, знижки не застосовуються взагалі.

Для **кошика** цей пошук відбувається один раз. Для **позицій** — окремо й незалежно для
кожної позиції, тож різні позиції можуть отримати різні набори.

Чи доступна конкретна знижка, вирішує логіка модуля або системи.

### Знаки чужої сутності в наборі

Знак у наборі виконує дві функції: **перевірочну** (задає умову, за якої набір узагалі
чинний) і **виконавчу** (задає порядок застосування).

Знак, що належить іншій сутності (знак позиції в наборі кошика чи навпаки), виконує **лише
перевірочну** функцію: він враховується під час перевірки набору й ігнорується під час
застосування.

**Набір для кошика** чинний, якщо всі вказані знижки кошика доступні для кошика, а кожна
вказана знижка позиції доступна хоча б в одній позиції.

**Набір для позиції** чинний, якщо всі вказані знижки позиції доступні для **цієї** позиції, а
всі вказані знижки кошика — для кошика.

## Що бачить покупець

У кошику й у спливному кошику показуються знижки з набору, який виявився чинним. Вибрати
набір, дізнатись, який саме застосувався, чи побачити інші можливі покупець не може. Після
оформлення застосовані знижки видно на сторінці замовлення.

У картці замовлення в адмінці параметри створених знижок можна змінювати, переставляти
місцями, видаляти й додавати нові — при збереженні вартість перераховується.

## Своя знижка з модуля

Два кроки: зареєструвати знак і додати знижку.

### 1. Реєстрація знака

Переклади назви й опису — у **бекендових** перекладах модуля:

```php
// Backend/lang/ua.php
$lang['discount_coupon_name'] = 'Купон';
$lang['discount_coupon_description'] = 'Купон, який покупець вводить у кошику.';
```

```php
public function init()
{
    $this->registerCartDiscountSign(
        'ok_coup',
        'discount_coupon_name',
        'discount_coupon_description'
    );
}
```

Для позиції — `registerPurchaseDiscountSign()` із тими самими аргументами
([modules/init-reference.md](modules/init-reference.md#знижки)). Реєструвати можна й будь-де
через `Discounts::registerPurchaseSign()` / `registerCartSign()`.

Повторний знак **позиції** кидає `Sign "…" is already exists`. Для знаків **кошика** ця
перевірка зараз не спрацьовує — умова звіряється з властивістю, якої в класі немає, тож
дубль знака кошика проходить мовчки й перекриває попередній.

### 2. Додавання знижки

Щоб набір зі знижкою міг застосуватись, знижку треба покласти в `availableDiscounts` —
кошика або конкретної позиції — з ключем, що дорівнює знаку. Робиться це розширенням
`Okay\Core\Cart::attachDiscounts()`:

```php
class FrontExtender implements ExtensionInterface
{
    public function attachDiscounts($cart)
    {
        $discount = new Discount();
        $discount->sign  = 'ok_coup';
        $discount->type  = 'absolute';
        $discount->value = 100;
        $discount->langParts['coupon'] = $_SESSION['coupon_code'];

        $cart->availableDiscounts['ok_coup'] = $discount;

        return $cart;
    }
}
```

```php
$this->registerChainExtension(
    [Cart::class, 'attachDiscounts'],
    [FrontExtender::class, 'attachDiscounts']
);
```

**Розширення має змінювати переданий об'єкт, а не покладатись на повернене значення.**
`attachDiscounts()` викликає розширення й повернене значення **не використовує** — працює це
лише тому, що `$cart` є об'єктом і зміни в ньому видно назовні.

Те, що метод оголошений `private`, розширенню не заважає: тригер спрацьовує зсередини самого
методу.

### Об'єкт `Discount`

`Okay\Core\Classes\Discount`:

| Властивість | Що це |
| ----------- | ----- |
| `$sign` | **обов'язкова** — знак знижки |
| `$type` | **обов'язкова** — `absolute` або `percent` |
| `$value` | **обов'язкова** — величина |
| `$fromLastDiscount` | режим обчислення; якщо не задано, береться з набору |
| `$name`, `$description` | мовні змінні (див. нижче) |
| `$langParts` | значення для підстановки в переклад |
| `$lang` | тимчасове сховище мовних змінних; заповнюється при підготовці знижок |
| `$priceBeforeDiscount`, `$priceAfterDiscount` | ціни до й після |
| `$absoluteDiscount`, `$percentDiscount` | величина знижки в грошах і у відсотках |
| `$id`, `$position` | ідентифікатор і порядок |

### Переклади й підстановки

`$name` і `$description` — це **імена мовних змінних**, які беруться з **фронтових**
перекладів, а не самі тексти. Якщо їх не задати при додаванні знижки, беруться ті, що вказані
під час реєстрації знака — саме імена, не переклади. Тобто однаково названі ключі в
бекендових і фронтових перекладах дозволяють не дублювати код.

У переклад можна підставляти динаміку. У самому перекладі (обов'язково **в одинарних
лапках**, щоб PHP не інтерполював) пишеться `{$var}`, а в `langParts` кладеться значення:

```php
// design/lang/ua.php
$lang['discount_coupon_description'] = 'Купон {$coupon}';
```

```php
$discount->langParts['coupon'] = $_SESSION['coupon_code'];
```

## Стандартні знаки

| Знак | Що це |
| ---- | ----- |
| `ok_coup` | купон; додається, якщо код валідний і сума замовлення не менша за мінімальну |
| `ok_gr` | знижка групи покупця |

Купон показується покупцеві навіть коли сума замовлення нижча за мінімальну — саме для цього
випадку в шаблоні є пояснювальна примітка; знижка при цьому не додається.
