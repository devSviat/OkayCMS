# vibe_shop Mobile Menu, Second Pass — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the off-canvas mobile menu read as one list instead of four visual languages, and move the close control to where a panel's close control belongs.

**Architecture:** Four of the five defects are CSS-only and live in the mobile-menu section of `components.css` (the run beginning at the comment "The markup is generated at runtime by mobile_menu.js (hc-offcanvas-nav)"). The fifth — relocating the close control — needs one option change in `scripts.tpl`, a small restructure of `mobile_menu.tpl`'s header row, and CSS. Social glyphs are added to `svg.tpl` in the stroke-based line style the rest of the set already uses.

**Tech Stack:** Smarty 4 templates; `hc-offcanvas-nav` (bundled build, no `ariaLabels` option); CSS in `design/vibe_shop/css/components.css`; verification via `puppeteer-core` driven directly.

**Spec:** `docs/superpowers/specs/2026-07-29-vibe-shop-mobile-menu-design.md`
**Branch:** `feature/vibe-shop-responsive` (PR #5, open — this work updates that PR)

## Global Constraints

- **Theme only.** Every change lands in `design/vibe_shop/`. Do not edit core, `design/okay_shop/`, or any module.
- **Class names generated by `hc-offcanvas-nav` cannot be renamed** — the library and `okay.js` both key off them. Only presentation is ours.
- **Three silent CSS compiler traps** in `Okay\Core\TemplateConfig\CssConfig`, which preprocesses this stylesheet line by line and errors on none of them: (a) a comment sharing a line with a declaration deletes that declaration — comments own their whole line; (b) `var(--okay-*)` substitutes only as `property: var(--okay-x);`, one call per line, no fallback; (c) a selector may break across lines only immediately after a comma.
- **`:has()` may not be nested inside another `:has()`** — CSS Selectors Level 4, enforced by the browser, silently drops the whole rule. Not a project quirk.
- **The `TOUCH TARGETS` block stays last in `components.css`.** Nothing goes after it.
- **Touch targets ≥44 px.** `.nav-item` carries `min-height: 52px`; do not reduce it.
- **Comment language: Ukrainian or English only, never Russian.** This file's comments are English.
- **Clear both caches after every edit** — templates change here, so Smarty's compiled output matters as much as the CSS bundle: `rm -f compiled/vibe_shop/*.php cache/css/*`
- **Commit messages carry no `Co-Authored-By` and no Claude/Anthropic attribution.**
- **`.superpowers/sdd/` is git-ignored scratch.** Stage only `design/vibe_shop/**`.
- **The menu does not exist until it is opened.** Every measurement clicks `.fn_menu_switch` and waits ~1.2 s.
- **Evidence before claims.** Every task states a measured value before and after.
