# Створення каталогів у ядрі: `recursive` і перевірка результату

**Дата:** 2026-08-06
**Беклог, з якого це виросло:** [2026-08-05-smarty-compile-dir.md](../plans/2026-08-05-smarty-compile-dir.md)

## Задача

`Okay\Core\Design::__construct()` створює каталог скомпільованих шаблонів так:

```php
if (!is_dir($this->smarty->getCompileDir())) {
    mkdir($this->smarty->getCompileDir(), 0777);
}
```

Без `recursive: true` створюється лише останній сегмент шляху. Якщо батьківського
`compiled/` немає, не створюється нічого, а `mkdir()` пише попередження і повертає `false`,
який ніхто не читає. У контейнері планувальника це попередження на кожному запуску
`ok scheduler:run`, тобто раз на хвилину.

## Що з'ясувалось під час розбору

Беклог припускав, що відкрите питання — чи є середовища, де `compiled/` навмисно відсутній.
**Репозиторій відповідає на це сам, і відповідь протилежна припущенню.**

- `Okay/xml/compiled/` і `backend/design/compiled/` возять у git файл `.keep_folder`, тож на
  свіжому клоні існують. У `compiled/` такого файлу **немає** — тобто на свіжому клоні немає
  й самого каталогу.
- Dev-образ це компенсує: `dev/docker/Dockerfile:95` робить `mkdir -p compiled …`, а
  `dev/docker-compose.yml:32` монтує туди tmpfs.

Тобто відсутність `compiled/` — не задум, а недогляд у git, який приховано на рівні
інфраструктури. Середовища, де він має лишатись відсутнім, не існує: без каталогу компіляції
Smarty не відрендерить жодної сторінки.

Далі, дефектів насправді два, і беклог називає лише перший:

| Дефект | Де |
| ------ | -- |
| немає `recursive` | `Design.php:181`, `ModuleDesign.php:155`, `ModuleCreateCommand.php:107`, `:124` |
| результат не перевіряється | ті самі чотири плюс `FrontTemplateConfig.php:83,87`, `BackendTemplateConfig.php:51,55`, `LicenseStorage.php:17` |

Правильна ідіома вже є в цьому репозиторії — `AttemptLimiter.php:84`:

```php
if (!is_dir($this->dir) && !@mkdir($this->dir, 0775, true) && !is_dir($this->dir)) {
    return;
}
```

Повторна перевірка `is_dir` після невдалого `mkdir` — не надмірність: два паралельні запити
обидва бачать `!is_dir`, обидва викликають `mkdir`, один програє гонку. Наївне
`if (!mkdir(...)) throw` дало б випадкові падіння під навантаженням.

## Рішення

**Обсяг:** усі дев'ять місць у ядрі приводяться до ідіоми `AttemptLimiter`, плюс
`compiled/.keep_folder` їде в git, як у двох сусідів.

**Поведінка при провалі:**

- `Design` кидає `\RuntimeException` зі шляхом у повідомленні. Без каталогу компіляції жодна
  сторінка не відрендериться — вона й зараз мертва, але гине з невиразним повідомленням
  Smarty про відсутній файл. Виняток називає причину одразу.
- Решта вісім місць — тихий вихід, як в `AttemptLimiter`: попередження зникає, поведінка не
  змінюється.

**Права `0777` не чіпаємо** — окреме питання, і зміна на `0775` може зламати розгортання, де
php-fpm і CLI ходять під різними користувачами.

### Виняток із «тихого виходу», який варто назвати

`ModuleCreateCommand` — інтерактивна CLI-команда, і тихий вихід із `recursiveCopy()` дав би
**мовчки недоскладений модуль**: рівно той клас дефекту, проти якого йде вся ця гілка. Тому
самі `mkdir` там тихі (як вирішено), але `createModuleFiles()` наприкінці звіряє, що каталог
модуля з'явився, і команда друкує помилку й повертає ненульовий код. Це звіт команди, а не
новий виняток поза `Design`.

## Тести

`Design` — накривається тестом: справжній `Smarty` (він дешевий) плюс стаби решти
залежностей. Провал `mkdir` відтворюється **батьком-файлом**, а не правами: `rootDir` вказує
всередину звичайного файлу, тож `mkdir` падає з `ENOTDIR`. Права для цього не годяться —
у контейнері тести можуть іти від root, який їх обходить, і тест був би зелений завжди.

Три випадки: каталог створюється рекурсивно, коли батька немає; наявний каталог не чіпається;
неможливість створити дає `RuntimeException` зі шляхом у повідомленні.

Решта восьми місць поведінково не змінюються (тихо було, тихо лишається), тож власних тестів
не отримують — їх покриває наявний набір.

## Межі

- Права `0777` — не чіпаємо.
- `chmod(0755)` у `ModuleDesign` лишається як є.
- `backend/design/js/filemanager/**` — вендорний код, не чіпаємо.
