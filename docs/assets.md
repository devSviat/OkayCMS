# CSS і JS

Файли стилів і скриптів **не підключаються тегами `<script>` і `<link>` у шаблоні**. Вони
описуються в конфігах теми чи модуля, а система збирає їх у спільні файли, мініфікує й
підключає сама.

## Де що описується

| Файл | Що реєструє |
| ---- | ----------- |
| `design/<тема>/css.php`, `design/<тема>/js.php` | асети теми |
| `Okay/Modules/<Vendor>/<Module>/design/css.php`, `design/js.php` | асети модуля на вітрині |
| `Okay/Modules/<Vendor>/<Module>/Backend/design/css.php`, `Backend/design/js.php` | асети модуля в адмінці |

Каталогу `design/css.php` у корені **не існує** — конфіги завжди належать конкретній темі або
модулю.

```php
// design/okay_shop/css.php
use Okay\Core\TemplateConfig\Css;

return [
    (new Css('grid.css')),
    (new Css('okay.css')),
    (new Css('theme.css')),
];
```

```php
// design/okay_shop/js.php
use Okay\Core\TemplateConfig\Js;

return [
    (new Js('okay.js'))->setPosition('footer'),
];
```

Файл шукається в `css/` або `js/` відповідної теми чи модуля. Тема може перевизначити асет
модуля, поклавши свій файл у `design/<тема>/modules/<Vendor>/<Module>/css|js/`.

## API опису

```php
public function __construct($filename)              // єдиний обов'язковий параметр
public function setDir($dir)                        // каталог відносно кореня сайта
public function setPosition($position)              // 'head' або 'footer'
public function preload()                           // додати <link rel="preload">
public function setIndividual($individual)          // не зливати у спільний файл
public function setAttribute(string $attribute, $value): Common
public function setAttributes(array $attributes): Common
public function setDefer($defer)                    // лише Js
```

Порожнє ім'я файлу кидає виняток, як і неіснуючий каталог у `setDir()` і позиція, відмінна
від `head`/`footer`. `setDefer()` діє тільки для файлів із `setIndividual(true)` — у
спільному зібраному файлі окремого `defer` бути не може.

## Smarty-плагіни `{js}` і `{css}`

Для разового підключення просто в шаблоні:

```smarty
{js file="lazyload.min.js" dir='design/vibe_shop/js' defer=true}
{css file='select2.min.css' dir='design/vibe_shop/css'}
```

`dir` — шлях від кореня сайту, який заміняє типовий `design/<тема>/{js,css}/`. Крім дерев
теми віддається ще й `js_libraries/` — місце для сторонніх бібліотек, спільних для тем.
У репозиторії його немає (єдиний мешканець, jssocials, прибраний), але маршрут лишається
в `.htaccess` і в конфігу nginx, тож покладена туди бібліотека віддаватиметься:

```smarty
{js file="lib.min.js" dir='js_libraries/lib/js'}
```

Параметри: `file` (або `filename`), `dir`, `defer` (лише `{js}`), `backend`/`admin` —
підключити в адмінці.

Віддалені адреси відхиляються: аргумент, що починається з `http://`, `https://` або `//`, не
підключиться.

**Пастка:** файл, підключений плагіном `{js}`, компілюється в `cache/css/`, а не в
`cache/js/` — у код передається каталог стилів. На роботу це не впливає, але шукати
скомпільований скрипт треба саме там.

## Складання

Зареєстровані файли зливаються в спільні набори (окремо `head` і `footer`), мініфікуються й
кладуться в `cache/css/` і `cache/js/`. Ім'я зібраного файлу — хеш від хешів складників, тож
зміна будь-якого файлу дає нове ім'я й нову адресу. Кожен складник у зібраному файлі
підписаний коментарем `/*! #File ім'я */`.

Скомпільовані файли, старші за тиждень, прибираються автоматично.

Директиви `preload_head_css`, `preload_head_js`, `preload_footer_css`, `preload_footer_js`
додають `<link rel="preload">` для відповідних наборів; `scripts_defer` додає `defer`
скриптам — [configuration.md](configuration.md).

## Налаштування теми: `theme-settings.css`

Кольори й інші змінні теми живуть у `design/<тема>/css/theme-settings.css` як CSS-змінні
(`--назва`). Адмінка редагує саме цей файл, а компілятор підставляє значення змінних у решту
стилів під час складання.

Читається файл повноцінним парсером CSS (`sabberworm/php-css-parser`), і **змінними стають
лише властивості з префіксом `--`**. Скануються всі набори правил, не лише `:root`, тож
змінна, оголошена деінде, теж потрапить у список, а остання перемагає.

Ім'я файлу задається параметром `them_settings_filename` — так, із помилкою в слові, це
реальне ім'я параметра.

Хеш цього файлу входить у ключ кешу зібраних стилів, тому зміна кольору в адмінці
перебудовує весь набір.

### Скільки кольорів насправді редагується

Свотч у «Дизайн → Налаштування дизайну» малюється лише для тієї змінної, для якої існує ключ
`settings_theme_<ім'я>` у `backend/lang/*.php` (ім'я — без `--`, дефіси замінені на
підкреслення). Таких ключів дев'ять, а `theme-settings.css` оголошує сімнадцять змінних:
решта вісім правляться лише руками у файлі. Тема не може додати собі десятий свотч — ключі
живуть у рушії, і додати їх може хіба модуль через власні переклади бекенду.

Через це `vibe_shop` розподіляє дев'ять слотів за видимістю на сторінці, а не за назвою:

| Свотч в адмінці | Що фарбує у `vibe_shop` |
| --------------- | ----------------------- |
| Додатковий корпоративний колір (+ колір тексту на ньому) | шапка й футер |
| Основний корпоративний колір (+ колір тексту на ньому) | смуга акційних товарів на головній |
| Кольори кнопок | кнопки й увесь темний інтерактив: пагінація, чипи, вкладки, підкреслення посилань |
| Колір фону сайту | полотно сторінки |

## Пастки CSS-компілятора

Компілятор **не парсер CSS, а построковий обробник**. Звідси кілька обмежень, які нічого не
повідомляють про себе — стиль просто не застосовується.

**Один `var()` на рядок.** Підстановка працює виразом, прив'язаним до всього рядка, тож
замінюється лише одне входження:

```css
color: var(--okay-basic-color);                       /* ✓ */
box-shadow: 0 0 2px var(--a), 0 0 4px var(--b);       /* ✗ підставиться щонайбільше одне */
```

**Оголошення має бути в один рядок.** `prop:` на одному рядку й `var(--x)` на наступному не
розпізнається.

**Запасне значення не працює.** `var(--x, #fff)` захоплюється як ключ `--x, #fff`, якого в
списку змінних немає, тож підстановки не буде взагалі.

**`var()` усередині `calc()`** або другим значенням у тому ж рядку — не підставляється.

**`/*` вважається початком коментаря будь-де**, зокрема всередині `url()` чи рядка.
Блоковий коментар коректно переживає перенос рядка, а от `//` як коментар не обробляється —
для CSS це правильно, для файлів у SCSS-подібному стилі ні.

**Рядки склеюються без роздільника.** Правило, записане в кілька рядків, збирається впритул:
селектори через кому це переживають, а от оголошення, розірване між рядками, — ні.

**Відносні шляхи правляться грубо.** Рядок, що містить `url` і `..`, отримує заміну всіх
`../` на шлях відносно нового розташування — включно з тими, що не є частиною шляху.

Тести на цю поведінку: `tests/Core/TemplateConfig/CssConfigBlockCommentTest.php`,
`tests/Core/TemplateConfig/CssConfigSettingsFileTest.php`.

## Вендорний CodeMirror в адмінці

`backend/design/js/codemirror/` — не повний реліз, а обрізаний дроп CodeMirror 5.65.18 із
дванадцяти файлів: дев'ять апстрімних, які підключають редактори шаблонів, стилів і
скриптів, сторонній `mode/smartymixed/`, а також `LICENSE` і `AUTHORS`. Решту дерева
(`demo/`, `doc/`, `test/`, `src/`, невживані режими, теми й аддони, `package.json`)
прибрано: під `backend/design/` усе віддається публічно за розширенням, тож кожен зайвий
файл був відкритим зразком версії бібліотеки.

`mode/smartymixed/` в апстрімі не існує — це сторонній режим, який тут і тримає підсвітку
Smarty поверх HTML. Оновлення CodeMirror має його пережити: він спирається на
`htmlmixed`-стан (`state.htmlState`) і на `tagName` зі стану `xml`, тому після кожного
апгрейду підсвітку `.tpl` треба відкрити очима, а не лише порахувати тести.

## Правки у вендорних файлах адмінки

Два файли під `backend/design/js/` відрізняються від апстріму, і обидві правки треба
переносити при кожному оновленні — інакше вони мовчки зникнуть.

**`jquery/jquery-ui.min.css` — шляхи до спрайтів.** Апстрім віддає
`url("images/ui-icons_*.png")`, і саме так воно зламалось би: компілятор CSS
переписує відносні шляхи **лише в рядках, де є `..`**
(`Okay/Core/TemplateConfig/CssConfig.php:350`). Без `..` рядок лишається як є, і
з `cache/css/` браузер шукає картинки поруч із зібраним файлом. Тому всі сім
посилань переписані на `url("../jquery/images/…")`. Шість файлів спрайтів лежать
у `backend/design/js/jquery/images/` і мають оновлюватись **разом** із CSS: між
1.12.1 і 1.14.2 однойменні файли різні за вмістом.

**`bootstrap-select.js` — `togglePlaceholder()`.** Метод порівнював `val()` з
`null`, а jQuery 3 для порожнього `multiple`-селекта віддає `[]`, тож клас
`bs-placeholder` перестав ставитись і підказка «Nothing selected» малювалась
основним кольором замість приглушеного. Апстрім полагодив це у 1.13 окремою
гілкою для `multiple`; тут та сама перевірка. Правка зникне разом із файлом,
коли плагін оновлять.

## jquery-migrate — тимчасовий

`jquery/jquery-migrate.js` стоїть у `js.php` одразу за jQuery і друкує в консоль
попередження про застарілі виклики. Це **міст, а не залежність**: його ставлять,
щоб побачити список того, що треба виправити, і знімають, коли список порожній.

Важливо для планування: migrate 3.x повертає `.size()` і `.andSelf()`, а
**migrate 4.x їх уже не повертає** — тобто до переходу на jQuery 4 наш код має
обійтися без них.

## Вендорний Highcharts в адмінці

`backend/design/js/highcharts/` — не повний дистрибутив, а три файли, які підключає
`stats.tpl`: `highcharts.js`, `themes/avocado.js` і `modules/exporting.js`. Повний
реліз важить 17 МБ і містить 558 файлів; решту (`es-modules/`, усі `*.src.js` і
`*.map`, `lib/`, `css/`, невживані модулі й теми) прибрано з тієї ж причини, що й
у CodeMirror: під `backend/design/` усе віддається публічно за розширенням.

`lib/` тримає `canvg`, `jspdf` і `svg2pdf` — вони потрібні лише `offline-exporting.js`,
якого адмінка не підключає. Якщо колись знадобиться експорт без звернення до сервера
Highcharts, ці файли доведеться повернути.

Ліцензія Highcharts комерційна, тож підняття мажорної версії — питання ліцензії
магазину, а не лише сумісності коду.

## Змінні з PHP у JS

```php
$design->assignJsVar('name', $value);
```

Читається в скриптах як `okay.name`. Маршрути з `'to_front' => true` доступні як
`okay.router['ім'я_маршруту']` ([routes.md](routes.md#генерація-url)).
