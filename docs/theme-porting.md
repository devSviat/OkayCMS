# Перенесення теми на цей форк

Цей форк змінив межі безпеки вітрини, і тема — не лише оформлення: вона бере участь у
захисті. Тема, написана під стокову OkayCMS 4.5.2, на форку працюватиме **частково**, і
ламатиметься тихо — HTTP 200, порожня консоль, порожній лог.

Тут перелічено все, що треба правити. Двигунова частина тих самих змін описана в
[UPGRADE-security.md](UPGRADE-security.md).

## `design/okay_shop` тут — адаптована тема, а не стокова

Штатна тема в цьому репозиторії **розходиться зі стоковою на 10 файлів**. Це свідомо: без
цих правок вона на форку не працює. Подивитись розходження:

```bash
git remote add upstream https://github.com/OkayCMS/OkayCMS.git   # один раз
git fetch upstream
git diff upstream/master main -- design/okay_shop
```

| Файл | Навіщо | Обовʼязково для форку |
| ---- | ------ | --------------------- |
| `js/okay.js` | CSRF-токен і POST для мутацій | так |
| `html/cart_purchases.tpl` | видалення з кошика: посилання → POST-форма | так |
| `html/pop_up_cart.tpl` | те саме у спливному кошику | так |
| `html/feedback.tpl` | токен у формі зворотного звʼязку | так |
| `html/password_remind.tpl` | форма встановлення нового пароля | так |
| `lang/{en,ru,ua}.php` | 6 ключів для тієї форми | так |
| `html/breadcrumb.tpl` | виправляє апстрімний баг | ні |
| `html/product_list.tpl` | виправляє апстрімний баг | ні |

Два останні до форку стосунку не мають: апстрімний шаблон звіряє `$controller` зі
значеннями `Comparison`, `LoginController` і `RegisterController`, яких у маршрутах немає
ні тут, ні в стоковій — тобто ці гілки не працюють і в самій OkayCMS. Виправлення лишені,
бо повернення до апстрімного варіанта відновило б баги.

## Що треба зробити у власній темі

### 1. Токен у кожній формі, що мутує

Змінна доступна в будь-якому шаблоні вітрини — її призначає `AbstractController`.

```smarty
<input type="hidden" name="customer_csrf_token" value="{$customer_csrf_token|escape}">
```

У штатних темах таких місць по шість.

### 2. Токен у кожному мутуючому ajax

Токен дублюється в куку `okay_csrf`, навмисно не `HttpOnly`, щоб скрипт міг її прочитати:

```javascript
function okayCsrfToken() {
  var match = document.cookie.match(/(?:^|;\s*)okay_csrf=([0-9a-f]{64})/);
  return match ? match[1] : "";
}
```

Далі `customer_csrf_token: okayCsrfToken()` у дані запиту і `type: "post"`. У штатних темах
шість таких викликів плюс два, де токен дописується до вже серіалізованої форми.

### 3. Видалення з кошика — форма, а не посилання

`/cart/remove/{variantId}` більше не GET. Посилання треба замінити на форму:

```smarty
<form method="post" action="{url_generator route="cart_remove_item" variantId=$purchase->variant->id}">
    <input type="hidden" name="customer_csrf_token" value="{$customer_csrf_token|escape}">
    <button type="submit">…</button>
</form>
```

### 4. Сторінка відновлення пароля

Посилання з листа більше не авторизує — воно веде на форму нового пароля. Шаблон має
обробити три стани: `$recovery_expired`, `$recovery_mode` і звичайну форму запиту листа.
Форма нового пароля надсилає `reset_password=1`, `new_password`, `new_password_check`.

Потрібні мовні ключі (див. `design/okay_shop/lang/ua.php`):
`password_remind_letter_sent_generic`, `password_remind_expired`,
`password_remind_password_empty`, `password_remind_password_wrong`,
`password_remind_new_password`, `password_remind_save`.

### 5. Не покладайтесь на `$_GET` у кошику, обраному й порівнянні

`cartAjax`, `wishlist` і `comparison` читають параметри з `$_POST`. Тема, що надсилає їх у
рядку запиту, отримає 403 або 405.

## Сумісність зі стоковою OkayCMS

Штатні теми ходять до кошика, обраного й порівняння через `okayAjax()`, який дублює
параметри і в тіло, і в рядок запиту: форк читає `$_POST`, стокова — `$_GET`. Токен
лишається тільки в тілі, щоб не потрапити в логи й `Referer`. Задум — щоб тему звідси
можна було поставити на стокову без правок.

Зворотне не працює: стокова тема на форку не пройде CSRF-перевірку.

**Наскільки це перевірено.** Стокову 4.5.2 підняли окремим стеком із гілки `master`:

- на PHP 8.5 вона **не стартує взагалі** — `aura/sql` падає з
  `Cannot make static method PDO::connect() non static`;
- на PHP 8.3 стартує і з темою з цього репозиторію віддає `/`, `/catalog`, `/cart` як `200`;
- ajax-ендпоінт кошика на тому ж стенді відповідає `500` **і на нашій темі, і на
  апстрімній, і на звичайному GET** — тобто ламається до того, як транспорт починає мати
  значення.

Отже дуальний транспорт лишається задумом, а не виміряним фактом: стокова 4.5.2 розрахована
на PHP 7.4/8.0, і зібрати для неї чесний стенд на доступних тут версіях не вийшло. Хто має
робочу стокову на PHP 8.0–8.2 — перевірка займе п'ять хвилин, і результат варто дописати сюди.

## Як переконатись, що тема жива

Зелені тести цього не доводять — вони не відкривають сторінок. Пройдіть руками:
додати в кошик, змінити кількість, видалити з кошика, додати в обране й порівняння,
надіслати форму зворотного звʼязку, підписатись на розсилку, відновити пароль.

Автоматично частину стереже `tests/Security/StorefrontCsrfGuardTest.php`: він перевіряє
обидві теми на наявність `okayCsrfToken`, `okayAjax` і потрібну кількість викликів. Якщо
ви додали свою тему в репозиторій — додайте її в провайдер цього тесту.
